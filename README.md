# 闲鱼定时助手 · XianyuScheduler

这是一个从干净仓库重新整理的版本。

## 保留部分
- 原有 UI 页面与底部导航
- 定时任务与自动任务调度
- 本地任务、视频任务、滑动/浏览任务
- ROOT 执行与任务状态验证
- 任务完成后的受控返回流程

## 新小游戏架构
水果小游戏不再继续维护旧的巨型决策类，而是拆成：

`截图 → 全棋盘视觉识别 → 不可变状态 → 状态搜索 → 单步执行 → 截图验证 → 立即重新规划`

每次点击后都重新建立当前棋盘状态；首击没有状态变化时直接废弃该候选并重新识别，不进入长时间“无动作”等待。弹窗关闭后同样立即重建棋盘。

当前阶段重点是先保证 UI/自动任务基线稳定，再继续用真实运行日志校准水果视觉识别与搜索参数。


## 4.45.0 水果求解器整改
- 棋盘识别区域重新按真实游戏画面校准：包含顶部水果，排除屋顶下方按钮区。
- 槽位只在屋顶中央收集区识别，不再把整条底部 UI 当作槽位。
- 水果外观距离加入小范围平移容差，降低同类水果因中心点漂移被判成不同类的概率。
- Planner 增加同类候选/最近邻诊断日志，出现“无安全动作”时可直接判断是视觉还是规划问题。
- 真实手指触摸只触发硬停止；不再启动真人教学窗口，不记录 TAP/SWIPE/WAIT，不回放真人操作。
- 保留“截图 → 识别 → 搜索 → 单组执行 → 截图验证 → 重规划”的闭环。


## 4.45.1 热修复
- 修复大量候选配对时 Planner 近似 O(n³) 导致搜索预算在 DFS 前耗尽、最终错误返回“无安全动作”。
- 配对距离与最近邻一次性预计算，候选动作限制为最高分 48 组；搜索超时仍回退到最佳根配对。
- 暂停把屋顶/装饰区域当成槽位占用，视觉槽位状态未知时不再伪报 tray=4。
- 增加水果页面状态机：复活、继续玩、开始游戏、功能弹窗和任务面板均优先处理，禁止把弹窗/任务面板送入水果识别。
- 删除“去完成”造成的假通关判断；只有明确的任务完成/过关/下一关文本才作为完成证据。
- 点击后一旦 OCR 已回任务面板，立即停止水果求解，不再把任务面板识别成 70+ 个水果。


## 4.45.2 水果物理与槽位修复
- 根据 13733.mp4 实机录屏修复：程序已能完成一组香蕉二消（208→206），但第一颗水果可能长时间滞留中央槽位。
- 槽位识别改为只检测屋顶之间的中央窄通道，拒绝屋顶、按钮和装饰造成的假 tray=4。
- Planner 新增向下落体通道阻挡估计；不再错误优先顶部水果，改为偏好靠近屋顶且向下通道更清晰的水果。
- 有槽内水果时优先执行单次 TRAY_MATCH，而不是继续盲点两个棋盘水果。
- 两个同类水果优先点击位置更低者，为第二颗水果释放下落路径。
- PAIR_FIRST 点击间隔由约 100ms 提升到约 0.5s。
- 动作后的 OCR 先运行，再采集结构验证截图，避免在水果仍处于下落动画时过早判失败。
- 若只确认一颗水果入槽，不记作失败；立即重规划并优先补齐槽内同类。


## 4.45.3 水果弹窗与验证修复
- 基于 13735.mp4 + 4.45.2 实机日志：已确认连续两组真实二消成功（206→204→202）。
- 将“解锁所有槽位/檀位 + 使用”识别为奖励道具弹窗；仅关闭弹窗，绝不点击视频/使用按钮。
- 奖励道具弹窗使用独立中央关闭区域白名单，避免继续把遮罩后的图案识别成水果。
- 当“剩余”计数前后都能读到时，计数器成为动作成功的最高优先级证据；计数不下降时，禁止用对象数量骤减覆盖结果。
- 仅在 OCR 计数不可用时允许结构变化兜底，且限制对象变化幅度，避免弹窗遮罩造成假成功。
- 当前局面中无效 Pair/TRAY_MATCH 会加入动作黑名单，重新规划时强制换候选，避免重复点击同一无效坐标。
- 成功计数下降后直接进入下一轮重新观察，不再额外做一次昂贵结构截图。
- 单局最大求解时间由 2 分钟扩展到 10 分钟，避免尚未通关就因固定 120 秒退出。
- 版本化游戏正文（VERSION + 剩余/剩小 + 消除 + 打乱）可直接识别为水果游戏，不再在安全停止后掉成 UNKNOWN_XIANYU。
- 物理触摸监听增加 1.2 秒启动保护，避免用户启动任务的触摸尾事件被误判为人工接管。
