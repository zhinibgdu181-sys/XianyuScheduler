# 闲鱼定时助手 · XianyuScheduler

这是一个从干净仓库重新整理的版本。

## 保留部分
- 原有 UI 页面与底部导航
- 定时任务与自动任务调度
- 本地任务、视频任务、跳转任务
- ROOT 执行与任务状态验证
- 任务完成后的受控返回流程

## 小游戏模块状态

自 4.48.0 起，小游戏任务已从产品功能中移除：界面不再提供小游戏开关，自动/定时执行不再扫描或进入小游戏，小游戏标题统一按不支持任务跳过。旧的水果/麻将求解器代码暂时保留为不可达兼容代码，不再有任何入口，后续可单独做源码清理而不影响现有任务模块。

## 历史：旧小游戏架构
水果小游戏不再继续维护旧的巨型决策类，而是拆成：

`截图 → 全棋盘视觉识别 → 不可变状态 → 状态搜索 → 单步执行 → 截图验证 → 立即重新规划`

每次点击后都重新建立当前棋盘状态；首击没有状态变化时直接废弃该候选并重新识别，不进入长时间“无动作”等待。弹窗关闭后同样立即重建棋盘。

当前阶段重点是先保证 UI/自动任务基线稳定，再继续用真实运行日志校准水果视觉识别与搜索参数。

- 删除“去完成”造成的假通关判断；只有明确的任务完成/过关/下一关文本才作为完成证据。
- 点击后一旦 OCR 已回任务面板，立即停止水果求解，不再把任务面板识别成 70+ 个水果。


## 4.45.2 水果物理与槽位修复
- 根据 13733.mp4 实机录屏修复：程序已能完成一组香蕉二消（208→206），但第一颗水果可能长时间滞留中央槽位。
- 槽位识别改为只检测屋顶之间的中央窄通道，拒绝屋顶、按钮和装饰造成的假 tray=4。
- Planner 新增向下落体通道阻挡估计；不再错误优先顶部水果，改为偏好靠近屋顶且向下通道更清晰的水果。
- 有槽内水果时优先执行单次 TRAY_MATCH，而不是继续盲点两个棋盘水果。
- 两个同类水果优先点击位置更低者，为第二颗水果释放下落路径。
- PAIR_FIRST 点击间隔由约 100ms 提升到约 0.5s。
- 动作后的 OCR 先运行，再采集结构验证截图，避免在水果仍处于下落动画时过早判失败。
- 若只确认一颗水果入槽，不记作失败；立即重规划并优先补齐槽内同类。


## 4.45.3 水果弹窗与验证修复

- 物理触摸监听增加 1.2 秒启动保护，避免用户启动任务的触摸尾事件被误判为人工接管。

## 4.45.5 无安全水果时空白恢复
- 修复“空白点击逻辑存在但几乎不触发”的问题：旧逻辑仅在 `plan.isEmpty()` 时执行，而实机常出现“有候选但点击无效”，因此不会进入空白恢复。
- 现在两类情况都会触发空白恢复：
  1. Planner 没有安全水果可点；
  2. 当前 Pair/TRAY_MATCH 点击后无消除、无入槽证据。
- 空白恢复在棋盘安全区域内交替执行：
  - 第一次：动态寻找离所有水果最远的空白点并点击；
  - 第二次：若整段路径都与水果保持安全距离，则执行约 70~150px 的短距离空白滑动；
  - 后续继续交替点击/短滑。
- 新增真正的 ROOT `input swipe` 执行接口；此前 FruitGameSolver.Host 只有 tap，实际上从未实现水果求解器的空白滑动。
- 空白滑动起点、终点和中间采样点都必须远离识别到的水果，并限制在游戏棋盘区域内，避免滑到“消除/打乱/解锁”等功能按钮。
- 一旦真实配对成功、单水果入槽成功或页面弹窗处理成功，空白恢复计数立即清零。

## 4.46.0 人类式连续配对
- 基于 13743.mp4 的真人玩法重构水果 Planner：不再预测未来 14 步，只看当前画面，选一对高置信同类水果，点击后立即重新观察。
- 删除“下方阻挡 >1 就禁止点击”的硬条件。下方水果只作为轻度降分，不再把人眼明显可点的同类水果直接排除。
- 同类身份反而更严格：高置信外观可直接配对；互为最近邻/单向最近邻使用更严格距离，避免再次出现橙子+番茄误配。
- 配对排序改为“身份相似度优先，其次偏好较低位置与较好可落性”；物理模型只排序，不拥有一票否决权。
- 最近邻救援同样取消下方阻挡硬门槛，但继续保持严格的同类距离。
- PAIR_FIRST→PAIR_SECOND 间隔缩短到约 180~280ms；第二次点击后等待约 320~480ms，再验证，接近真人连续点击节奏。
- UI 全量探测间隔由 0.9s 放宽到 2.2s；动作前/动作后仍有 OCR 页面守卫，减少无意义重复 OCR。
- 4.45.6 的左右砖墙固定保活仍保留，只在确实没有可靠配对或候选验证失败时使用。


## 4.46.1 主动死局突破
- 取消 4.45.6 的左右砖墙固定点击/固定滑动保活：不再通过无意义空白输入拖时间。
- 核心原则改为：绝不能无限等待；没有完美选择时主动改变游戏局面。
- 槽内出现 2 种不同水果且当前没有严格同类可补时，启动 2 秒忍耐计时；这 2 秒仍可继续正常二消，但计时不会因为消掉无关 Pair 自动清零。
- 槽内达到 3 种不同水果且没有同类可补时，不等待 2 秒，立即进入死局突破。
- 死局突破优先级：
  1. 严格按外观身份寻找槽内同类；允许忽略物理阻挡，绝不放宽水果身份；
  2. 仍无槽内同类时，主动点击游戏“打乱”按钮重新洗牌；
  3. 不点击“消除/使用/视频”，奖励弹窗仍由现有状态机安全关闭。
- 连续候选无效或完全没有可靠 Pair 超过 2 秒，同样触发“打乱”，不再空等。
- 无效单水果候选按坐标加入黑名单，普通 TRAY_MATCH 与 DEADLOCK_TRAY_MATCH 不会换个 reason 重复点同一颗。
- 新增日志：trayTypes、死局计时开始、2 秒超时、3 种槽位立即破局、主动打乱。


## 4.47.0 三槽模板状态机
- 按游戏真实规则重写水果小游戏决策，不再用“相似度 Pair + 风险猜测”决定下一步。
- 槽位物理容量按 3 个处理；允许观测到第 4 颗短暂叠加状态，但此时只等待游戏自动消除/失败，不再追加点击。
- 初始模板库来自实机截图 13738.jpg 中 15 类水果的 7×7 RGB 模板特征。模板不确定或第二候选过近时返回 `UNKNOWN_TEMPLATE`，绝不强行归类。
- 只有“模板类别明确 + 判定未被其他水果覆盖”的水果允许点击。
- 决策树：
  1. 槽位 0：点击当前未遮挡水果中数量最多的一类。
  2. 槽位 1：优先点击槽内同类；没有时点击未遮挡数量最多的一类。
  3. 槽位 2 且 A,A：只点击 A。
  4. 槽位 2 且 A,B：只允许点击 A 或 B；全场无未遮挡 A/B 时立即死局重开。
  5. 槽位 3 且 A,B,C：只允许点击 A/B/C；全场无匹配时立即死局重开，绝不点击新种类 D。
- 槽位出现 UNKNOWN_TEMPLATE 时不冒险；连续 3 帧仍无法识别则自动重开。
- 死局不再“打乱”、不再点空白墙：OCR 优先寻找“重新开始/重开/再来一局”；若仍在棋盘，则先打开左上设置，再识别重开按钮并确认。
- 单次点击后重新截图验证模板状态；完全无变化的坐标加入黑名单，不重复点击。
- 一个自动小游戏任务内部可以自动重开并继续，直到通关或安全停止。


## 4.47.1 栈顶二消规则修正
- 关键规则修正：槽位不是无序集合，而是垂直栈；只有当前栈顶水果能和新掉入水果形成相邻二消。
- 槽位按屏幕 y 从大到小保存为“底→顶”顺序。
- 例：底A / 中B / 顶A 不会自动消除，因为两个 A 被 B 隔开；若再点击一个未遮挡 A，新 A 与栈顶 A 相邻后才可二消。
- 槽位1个 A：优先点 A；若没有 A，可选择数量最多的新类型作为第二层。
- 槽位2个 A(底),B(顶)：只允许点 B；场上即使有 A，也不能解决当前栈顶，找不到 B 即判死局重开。
- 槽位3个 A,B,C（C为顶）：只允许点 C；A/B/D 都不能触发顶部二消。没有未遮挡 C 时立即死局重开。
- 只有“顶部两颗已经同类”时等待自动二消；下层存在同类但被其它水果隔开时不等待。
- 新增 A/B/A 不自动消除、A/B/C 只允许 C、A/B 只允许 B 等回归测试。

## 4.48.0 移除小游戏任务模块
- 自动化页面删除“小游戏任务”开关与说明卡片。
